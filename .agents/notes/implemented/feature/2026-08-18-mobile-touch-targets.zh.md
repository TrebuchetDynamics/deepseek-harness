# Agent Note: 移动端触控目标尺寸

Status: implemented

[English](2026-08-18-mobile-touch-targets.md) | 中文

## 问题

对 shell 的 390px 视口审计发现，所有主要移动端控件对于频繁触控而言尺寸过小：侧边栏控制栏按钮为 36x36（共五个控件），输入框发送圆形按钮 34x34，附件/命令触发器 28x28，计划/模式选择器与英雄区工作区触发器均为 28px 高。小尺寸目标在触控设备上让导航与发送更容易误触，也是移动端 shell 显得"过于拥挤"的主要因素。

## 决策

采用纯 CSS 移动端规则，断点与布局层用于侧边栏自动折叠的窄屏断点一致（`max-width: 1023px`）。56px 控制栏宽度是契约冻结的，因此控制栏控件通过将两侧内边距从 10 收窄到 6px 来放大到 44px（44 + 2*6 = 56）。两个由 slot 持有的控制栏控件（工作区添加/搜索对与设置触发器）也在同一断点下放大到 44px。输入框发送与附件/命令控件从 34/28 放大到 40px，计划/模式选择器获得 40px 高度下限，英雄区工作区触发器获得 40px 最小高度。桌面端几何不变：规则位于媒体查询内，基础声明未改动（sidebar-styles spec 仍固定 36px 的桌面控制栏）。

## 备选方案

**改为加宽移动端控制栏。** 已否决：SIDEBAR_COLLAPSED 是布局求解器测试所断言的契约冻结几何；在现有 56px 控制栏内放大控件无需改动任何常量或求解器。

**用伪元素扩展命中区域（不可见的 44px 目标）。** 已否决：直接放大尺寸更简单、可直接验证，而且更大的尺寸正是本次改进的目的。

## 影响

在窄视口下，控制栏、输入框发送、附件、模式选择器与英雄区工作区触发器达到 40-44px 的触控下限；桌面端不变。样式契约 spec（ui-sidebar 的 sidebar-styles 测试与新增的 ui-conversation mobile-touch-targets 测试）固定了媒体查询规则；完整客户端 GUI 测试套件与客户端类型检查均通过。在重建后的 390px bundle 上，全部五个控制栏控件均测量为 44x44 且无水平溢出；样式契约 spec 覆盖了每个所有者（sidebar-styles、browser-styles、settings-root-styles、mobile-touch-targets）。
