# Agent Note: 移动端覆盖式抽屉

Status: implemented

[English](2026-08-18-mobile-overlay-drawer.md) | 中文

取代 [移动端侧边栏轻触关闭](2026-08-18-mobile-sidebar-light-dismiss.zh.md) 中"透明背景"的备选方案理由；其中点击外部／Escape 的关闭机制不变。

部分被 [移动端侧边栏浮动唤起按钮](2026-08-18-mobile-fab-sidebar-opener.zh.md) 取代：窄屏关闭态现在完全隐藏（无 56px 控制栏），改由浮动按钮唤起；本文所述的抽屉覆盖行为不变。

## 问题

在窄视口下，展开的侧边栏会挤压主区域，390px 宽度下仅剩约 110px 的细条，而不是覆盖在会话之上：会话被重排进无用的细条，且轻触关闭背景是透明的，抽屉不呈现模态感。移动端抽屉应在变暗的背景层之上覆盖其表面（标准的导航抽屉模式）。

## 决策

AppFrame 将侧边栏保留为普通网格项，因此折叠滑动仍沿用现有的网格轨道过渡，SidebarRoot 的冻结宽度阶段不受影响。当处于窄屏且展开状态（frame 上带 `data-drawer`）时，侧边栏占据第 1 行第 1 列，主区域则在第 1 行跨越所有轨道（`grid-column: 1 / -1`），会话在抽屉后保持全宽；侧边栏列提升到其上（`z-index: 12`）。轻触关闭表面变为全屏背景层，只要处于窄屏便挂载，并随滑动淡入淡出（`--dsw-alias-bg-mask-2`，比模态框的 mask-1 更浅），仅在抽屉展开时可见且可点击；点击它或按 Escape 即通过现有 `closeSidebar` action 折叠。窄屏抽屉固定为约定默认宽度，因此触控布局不再渲染其缩放手柄。

## 备选方案

**保留挤压并只调暗细条。** 已否决：110px 的调暗内容条读起来像布局损坏，而非模态效果；抽屉后的会话必须保持完整比例。

**将侧边栏绝对定位移出网格。** 已否决：那会绕过网格轨道滑动并迫使并行宽度动画，破坏 SidebarRoot 的冻结宽度淡出阶段；让侧边栏留在文档流中即可保留整套折叠机制。

## 影响

在窄视口下，展开的侧边栏是真正的覆盖式抽屉：背后是铺满全宽且变暗的会话，点击外部或按 Escape 关闭，无缩放手柄。桌面端不变（无背景层，手柄照旧）。app-frame 与 app-frame-styles 客户端 spec 覆盖了覆盖状态、常驻挂载的淡入淡出背景，以及窄屏移除手柄的行为；无密钥的 mobile-sidebar-drawer 浏览器场景在 Chromium 中验证了首行重叠几何。
